# ストーリー品質評価 (INVEST原則)

このドキュメントは、`.story/story.yaml` に記載された各ユーザーストーリーが、高品質なストーリーの指針であるINVEST原則を満たしているかを評価します。

- **I**ndependent (独立しているか)
- **N**egotiable (交渉可能か)
- **V**aluable (価値があるか)
- **E**stimable (見積もり可能か)
- **S**mall (小さいか)
- **T**estable (テスト可能か)

---

## Epic: VS Code拡張でYAML形式ストーリーのスニペット

### Story: YAMLスニペットの提供

| 原則 | 評価 | 理由 |
|:--- |:--- |:--- |
| **I**ndependent | ✅ | 他のストーリーに依存せず、単独で実装可能です。 |
| **N**egotiable | ✅ | スコープ（どの要素のスニペットを提供するか）は明確で、交渉の余地がありました。 |
| **V**aluable | ✅ | ユーザーが迅速にYAMLを作成できるという明確な価値を提供します。 |
| **E**stimable | ✅ | `points: 8` として見積もり済みです。 |
| **S**mall | ✅ | 1スプリントで完了可能な適切なサイズです。 |
| **T**estable | ✅ | DoDが具体的で、スニペットの呼び出しや種類をテストできます。 |

## Epic: VS Code拡張でのYAML形式ストーリーのプレビュー

### Story: テーブル形式プレビュー

| 原則 | 評価 | 理由 |
|:--- |:--- |:--- |
| **I**ndependent | ⚠️ | 「アイテム詳細表示」ストーリーへの言及があり、弱い依存関係が存在します。 |
| **N**egotiable | ✅ | 表示する列の定義など、実装前に交渉可能な要素が含まれていました。 |
| **V**aluable | ✅ | ストーリー構造を視覚的に確認できるという中心的な価値を提供します。 |
| **E**stimable | ✅ | `points: 13` として見積もり済みです。 |
| **S**mall | ⚠️ | 13ポイントは比較的多きく、リアルタイム反映などを含むため、より小さなストーリー（例：「静的なテーブル表示」と「リアルタイム更新」）に分割する余地がありました。 |
| **T**estable | ✅ | DoDが具体的で、表示内容やエラーハンドリングのテストが可能です。 |

### Story: アイテム詳細表示

| 原則 | 評価 | 理由 |
|:--- |:--- |:--- |
| **I**ndependent | ⚠️ | 「テーブル形式プレビュー」でアイテムをクリックすることが前提となっており、依存関係があります。 |
| **N**egotiable | ✅ | 表示する詳細項目は交渉可能です。 |
| **V**aluable | ✅ | YAMLを直接見ずに詳細を確認できる価値があります。 |
| **E**stimable | ❌ | **ポイントが見積もられていません。** |
| **S**mall | ❓ | 見積もりがないため、サイズの評価が困難です。 |
| **T**estable | ✅ | DoDが具体的でテスト可能です。 |

| **T**estable | ✅ | DoDが詳細なためテストは可能ですが、1ストーリーに対するテスト範囲が広大になります。 |

## Epic: 拡張機能の最適化

### Story: YAMLファイル編集時のみ拡張機能を有効化

| 原則 | 評価 | 理由 |
|:--- |:--- |:--- |
| **I**ndependent | ✅ | 他の機能開発とは独立した、拡張機能全体に関わる設定変更です。 |
| **N**egotiable | ❌ | 実装方法（`package.json`の`activationEvents`）が指定されており、交渉の余地は少ないです。 |
| **V**aluable | ✅ | 開発者（ステークホルダー）にとって、リソース効率化という明確な価値があります。 |
| **E**stimable | ✅ | `points: 3` として見積もり済みです。 |
| **S**mall | ✅ | 適切なサイズです。 |
| **T**estable | ✅ | `package.json`の記述や、実際の拡張機能の有効化タイミングをテストできます。 |
